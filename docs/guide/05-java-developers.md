# How AussomCraft Works

For people reading or changing the Java, not for people writing scripts. If
you want to write scripts, start at [What AussomCraft is](01-overview.md).

## The problem this solves

A Paper plugin runs as part of the server, with everything the server can
reach. AussomCraft runs scripts inside that plugin, including scripts the
operator did not write and has not read. The whole design answers one
question: how do you let a stranger's code run in your process without
handing it your process?

The answer is that a script never gets a general way into Java. It gets a
list of methods, and that list is decided when the code is generated rather
than when the code runs.

---

# Part 1: The building blocks

Four things have to make sense before the rest does.

## The Aussom engine

`com.aussom.Engine` parses `.aus` source and runs it. One engine per loaded
script, never shared. An engine is built with a `SecurityManagerInt`, which
is a bag of named properties the interpreter consults, and that object is
the entire policy: what a script may reach is decided by what those
properties say.

Two properties matter most:

- `aussom.extern.allowed` lists the Java classes an `extern class`
  declaration may name.
- `aussom.aji.*` decides whether AJI exists at all.

## The two doors into Java

Aussom reaches Java in exactly two ways, and both are gated.

**An `extern class`** binds an Aussom class to a Java class:

```
extern class Player : com.lehman.aussomcraft.paper.gen.untrusted.PlayerShim {
    public extern getName();
}
```

The Java method behind `getName` must have this exact shape:

```java
public AussomType getName(Environment env, ArrayList<AussomType> args)
```

That signature requirement does more work than it looks like. An ordinary
Java method such as `PaperObj.setObj(Object)` is public, but it does not
have the extern calling convention, so no script can declare it and no
script can attach an object of its own choosing.

**AJI** is a reflection API: name a class, construct it, call methods on it.
It reaches anything on the class path. Only the dangerous tier has it.

## The class loader

Paper starts through Paperclip, and the server loader's parent is the
platform loader, not the application loader. So `getSystemClassLoader()`
cannot see `org.bukkit` at all.

Anything resolving class names by string has to be told which loader to use.
`AjiGate.setClassLoader` is called at plugin enable, and each policy carries
an `engineClassLoader`. Getting this wrong does not fail loudly: names
silently stop resolving.

## Tiers are a generation decision

This is the idea the rest of the design hangs on.

There are three tiers: **untrusted**, **trusted**, **dangerous**. A tier is
not a set of runtime permission checks. It is a directory of generated
Aussom modules:

```
aus/paper/untrusted/     23 modules
aus/paper/trusted/     1485 modules
aus/paper/dangerous/   1563 modules
```

The two upper tiers are generated by rule from Paper's API. Untrusted is
not: it is a hand written list of 57 method names, with its types and events
named one at a time, in `src/gen/resources/untrusted-allowlist.txt`. Rules
match on name shape, and what matters is capability, so the rules kept
granting untrusted things nobody had chosen. The shims are still generated
from that list by the same code path as the other tiers, which is what keeps
a script working unchanged when it is elevated.

A module declares the methods that tier grants for one Paper type. A method
a tier withholds is not written into that tier's module, so it does not
exist for a script at that tier. There is nothing to refuse at runtime,
because there is nothing to call.

# Part 2: The pieces

## Build time, in `src/gen`

These four classes never ship. They run under `mvn exec:java` and write the
generated API into the source tree, where it is committed and reviewable in
a diff.

| Class | What it does |
| --- | --- |
| `gen.Generator` | walks `paper-api.jar`, plans each type, writes the shims and the modules |
| `gen.Rules` | decides the tier of every method and type, and what is expressible |
| `gen.Tier` | the three tiers, and which includes which |
| `gen.Docs` | reads parameter names out of the sources jar |

`Rules` is where the security decisions live. `Rules.tierOf(Class, Method)`
returns the tier a method belongs to, and `Rules.typeAllowed(Class, Tier)`
decides whether a tier can even express a type. A method naming a type the
tier cannot express is dropped rather than moved.

## Runtime: the generated API, in `paper`

| Class | What it does |
| --- | --- |
| `paper.gen.<tier>.<Type>Shim` | generated. One class per Paper type per tier, 3,346 of them |
| `paper.PaperObj` | base of every shim. Holds the wrapped Bukkit object |
| `paper.Marshal` | converts between Aussom values and Java values, and builds shims |
| `paper.PaperModules` | reads the generated modules out of the jar and registers them per engine |
| `paper.TierAware` | lets the marshaller ask an engine which tier it is |

The generated shims are worth understanding, because they are where the tier
boundary actually lives.

There is one class per Paper type **per tier**, and it carries only that
tier's methods. `untrusted.PlayerShim` does not contain `setOp`. Not hidden,
not refused at runtime: absent.

Each method calls Paper directly:

```java
public AussomType getName(Environment env, ArrayList<AussomType> args) {
    org.bukkit.entity.Player self = (org.bukkit.entity.Player) this.getObj();
    if (self == null) {
        return Marshal.detached("getName");
    }
    int n = 0;
    if (args != null) {
        n = args.size();
    }
    try {
        if (n == 0) {
            return Marshal.wrap(env, ((org.bukkit.entity.Player) self).getName());
        }
        return Marshal.wrongArity("getName", n);
    } catch (Throwable e) {
        return Marshal.failed("getName", e);
    }
}
```

Two things about the shape. There is one Java method per extern **name**, not
per signature, because every extern binds the same Java form
`name(Environment, ArrayList)`; two arities of one name are one method that
branches, and each branch is a fixed typed call. And the receiver is cast to
the raw declaring type, which is how a generic such as `OldEnum<Art>` stops
being a compile error.

Tiers do not inherit. `trusted.PlayerShim` declares everything itself rather
than extending the untrusted one. That doubles the generated code, and it
means "does this tier grant this method" is answered by reading one file.

An earlier design had a single shared class, `PaperApi`, holding every method
for every tier, reached by reflection. It is worth knowing why it went, since
the reasoning is the design:

- Aussom gates `extern class` on the Java class name. One shared class gave
  a per-tier allowlist nothing to distinguish, so the interpreter's own
  security mechanism could not be used at all.
- Reflection resolved a call on the method **name** against the receiver's
  live Java class, which is not the set the generator emitted.
- Nothing checked generated code against Paper, so a renamed Paper method
  failed on a running server rather than at build time.

## Runtime: the host API, in `host`

The externs a script calls directly. These are hand written, and they are
the only way a script registers anything with the server.

| Class | Extern | What it does |
| --- | --- | --- |
| `host.Host` | - | shared helpers: find the script from an `Environment`, convert values |
| `host.HostEvents` | `events` | registers Bukkit event handlers |
| `host.HostCommands` | `cmd` | registers commands in the server's command map |
| `host.HostScheduler` | `sched` | schedules tasks |
| `host.HostStore` | `store` | per-script persistent key/value data |
| `host.HostServer` | `server` | broadcast, tell, look up players |

An extern gets an `Environment` and nothing else. `Host.context(env)` walks
`env.getEngine()`, which is a `ScriptEngineHost`, and asks it which script it
is running. That is how `events.on` knows whose handler it is registering.

That every registration goes through these classes is what makes unload
work. `ScriptContext` records what was handed out, so it can all be taken
back.

## Runtime: loading and running, in `script`

| Class | What it does |
| --- | --- |
| `script.ScriptLoader` | reads a file, picks its tier, builds an engine, runs `main` |
| `script.ScriptContext` | one loaded script: its file, hash, tier, engine, and registrations |
| `script.ScriptEngineHost` | an `Engine` that knows which script it is |
| `script.Runner` | the one place a script callback is called |
| `script.Watchdog` | stops a run that goes past its budget |

`Runner` exists so budget accounting, cancellation and error reporting are
written once. Events, commands and scheduled tasks all funnel through it. A
handler that throws must not take the event with it, so every failure is
logged against the script and swallowed.

`Watchdog` runs one thread that watches the runs in flight and calls
`Engine.cancel()` on any that overrun. Cancellation is cooperative: the
interpreter checks its control state at loop edges and calls. Three limits
are worth knowing and are written in the class comment: the tick has already
stalled by the time it fires, a script inside one long AJI call has no
checkpoint, and a cancelled engine still holds its memory.

## Runtime: trust and policy

| Class | What it does |
| --- | --- |
| `trust.TrustStore` | which exact scripts an operator has elevated |
| `profile.Profile` | the three tiers, and how to build a policy for one |
| `profile.UntrustedPolicy` | the base policy: no AJI, a short extern allowlist |
| `profile.TrustedPolicy` | the same policy. The tier is the modules, not the policy |
| `profile.DangerousPolicy` | turns AJI on and widens the extern allowlist |

A grant is keyed on the SHA-256 of the script's bytes, never its path. So
moving a file does not change what it may do, and editing one silently
revokes its grant.

`TrustedPolicy` extending `UntrustedPolicy` and changing nothing is not an
oversight. Trusted differs from untrusted only in which generated modules
the loader registers. There is no Java gate between them.

## Runtime: AJI, in `aji`

Ported from aussom, dangerous tier only.

| Class | What it does |
| --- | --- |
| `aji.AjiGate` | the single place AJI asks whether an operation is permitted |
| `aji.AussomAJI` | the `aji` extern: construct, invoke, static access |
| `aji.AussomJavaObject` | a wrapped Java object a script can call methods on |
| `aji.SandboxDenied` | the exception a denial raises |

`AjiGate` has one allowlist. Denial is absence. Entries take three forms:
`*` admits everything, `pkg.*` admits by name prefix, and `a.b.C` admits
anything assignable to that type. Both forms are needed: assignability
reaches `CraftPlayer` from `org.bukkit.entity.Player`, which no package
prefix would match.

# Part 3: Two walkthroughs

## Loading a script

`AussomCraftPlugin.reloadScripts()` calls `ScriptLoader.load` for each file.

1. Read the file once. Hash those bytes and take the source from the same
   bytes, so there is no window where the two differ.
2. `TrustStore.profileFor(hash)` gives the tier. No grant means untrusted.
3. Build the policy for that tier and a `ScriptEngineHost` under it.
4. `PaperModules.install` registers that tier's modules on the engine and
   includes the common core types.
5. Build the `ScriptContext` and seed its store from `store.yml`, before the
   script runs, so `main` can read what the last run saved.
6. Include `craft.aus`, and `aji.aus` only at the dangerous tier.
7. Parse.
8. Check that the script has not declared a class named after a generated
   shim. See below for why.
9. Run `main` under the watchdog, on a larger budget than a handler gets.

Any failure detaches whatever the script managed to register and returns
null, so a half-initialised script never keeps handlers.

## An event reaching a script

A player joins.

1. Bukkit calls the `EventExecutor` that `HostEvents.on` registered.
2. `AussomCraftPlugin.wrapEvent` calls `Marshal.shim`.
3. `Marshal.shimNameOf` walks the object's class and interfaces to the first
   Paper API type, and returns its simple name: `PlayerJoinEvent`. Paper
   hands out implementation classes, so this step is what gets from
   `CraftPlayer` to `Player`.
4. If the engine has no class by that name yet, `PaperModules.includeType`
   parses that tier's module now. The parse is charged to the host, not the
   script, through `TierAware.hostWorkDone`.
5. `Engine.instantiateObject` builds the shim, and `setObj` attaches the real
   Bukkit object to it.
6. `Runner.run` calls the script's callback with that shim, inside the
   watchdog.
7. The script calls `Evt.getPlayer()`. That is
   `untrusted.PlayerJoinEventShim.getPlayer`, a plain Java method.
8. It casts the wrapped object, calls Paper, and wraps the result with
   `Marshal.wrap`, which starts this process again for whatever came back.

If the tier has no module for a returned type, the shim comes back null.
That is the same answer as a method the tier does not have.

# Part 4: Where the boundary is

**It is in the generator.** A method a tier withholds is absent from that
tier's module. Nothing checks a permission at call time because there is
nothing to check.

**One runtime check backs it up.** Shim classes live in one flat namespace
under their simple name, and modules are installed before the script parses.
A script that declared its own class named `Player` would displace the
generated one, and the host would then attach a real `Player` to a class the
script wrote, with whatever methods it chose. `ScriptLoader.shimCollision`
refuses such a script at load, comparing the live class's method list
against what the tier's module declares.

**And the interpreter refuses the name.** Each tier's policy admits only its
own shim package:

```
untrusted:  com.lehman.aussomcraft.paper.gen.untrusted.*
trusted:    com.lehman.aussomcraft.paper.gen.trusted.*
dangerous:  com.lehman.aussomcraft.paper.gen.dangerous.*   plus AJI
```

`com.lehman.aussomcraft.paper` itself is on no list, so `Marshal` and
`PaperObj` cannot be named by any script either.

So a method is withheld three ways over: the module does not declare it, the
Java class does not have it, and the allowlist will not let a script name a
class that does. Any one failing still leaves two.

**Some things are not boundaries at all.** The watchdog bounds a runaway
handler, not a hostile one. `store.max-bytes` bounds disk use. Neither is
part of the tier model; they are there so one bad script cannot spoil the
server for everyone.
